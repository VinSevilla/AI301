# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff within plan | The diff's changed files and hunks, read against the plan's stated files, scope, and "not in scope" list plus any deviation note. | Every changed file and hunk is part of the plan's change or covered by a recorded deviation note. Any hunk outside both (a new option or flag, a rename or refactor pass, an edit to a file the plan never names, a rewrite of unrelated code) fails, even if the description discloses it, unless the plan or its deviation note covers it. Fails even when the extra work is adjacent or looks harmless. | required |
| Plan delivered and claims match | The plan's list of steps and deliverables, and the description's Summary, Changes, and fidelity claims ("implements the plan exactly", "docs updated", "no changes outside X"), each read against what the diff actually contains. | Every deliverable the plan promises is in the diff, or the plan's deviation note or the description plainly says it was deferred or changed and why. Every claim the description makes about the change is visible in the diff. A promised piece missing with no disclosure, or a description claiming something the diff does not contain, fails. An honestly disclosed deferral passes. | required |
| Decisive test evidence | The test-evidence section's before/after, read against the plan's test plan and the repro steps in the plan's repro evidence. | The evidence re-runs the plan's own repro or named check on the changed code and shows an observable before and after result that distinguishes the bug from the fix. All failure modes the plan's test plan names are exercised, or the omission is disclosed. Fails if the evidence is only an assertion ("tested locally", "works on my machine", "tests pass") with no output, if it exercises a different or unchanged path (a control case, a different input) instead of the plan's repro, or if the test added covers behavior the fix did not change. | required |
| Repo checks run | The test-evidence section and the description's Testing section, read against the repo's stated checks (the PR template's checklist, the repo-facts commands). | The repo's stated checks (test suite, lint, typecheck, pre-commit, whichever the template or contribution guide names) were run and their outcomes are shown, with output or a plain pass/fail result. A check that failed or could not run passes if the outcome and reason are stated honestly. A check named by the repo and never mentioned, or a claim "all checks passed" with no outcome shown, fails. | required |
| Clean diff | The diff's hunks and the commit list. | The diff contains no debris: no debug prints or leftover logging, no commented-out code, no dead or unused functions or imports added, no unresolved TODOs added, and no formatting, whitespace, or re-indentation churn on lines the fix does not need to touch. Mechanical churn around a correct fix still fails. Commit messages like "wip" or "misc cleanups while debugging" are supporting evidence, not the test. | required |
| Template and stated asks | The description, read against the repo's PR template sections and checklist and the contribution guide's stated asks in the repo facts (issue reference such as `Closes #N`, tests, changelog or whatsnew entry, type annotations, and so on). | Every template section has real content for this PR, not boilerplate or blank, and ticked boxes are true. Each ask the repo states is met by the description or by the diff (an asked-for changelog entry or test is in the diff; the issue is referenced). A visibly ignored section, an unticked or false checklist item, or a stated ask with no sign in the PR fails. If the repo states no template or asks, pass. | required |
| AI disclosure | The description, read against the AI-use policy in the repo facts or CONTRIBUTING.md. | If the repo states an AI-use or disclosure policy, the description discloses the AI use the policy asks for, naming the tool and how it was used, in the student's own words. In eval mode treat every package as AI-assisted. If the repo states no AI policy, pass. A policy that exists with no disclosure in the description fails. | required |
| Reviewable commits | The commit list. | Commits are small, each message says what changed. | preferred |

## Verdict rule

Accept (ready to submit) only if every required check passes. Reject (hold) if any required check fails or is unclear. `unclear` on a required check counts as fail: a PR that cannot be verified from the package is not ready. Preferred checks never change the verdict; record their grades, including `unclear`, in the output. A disclosed shortfall is not a failure: a PR that honestly states what it deferred or changed passes the checks above on what it says it delivers.
